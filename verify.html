Hardware-Attested PayPal Login

Prove the machine handling your PayPal login is genuine confidential-computing hardware — then log in.

There is deliberately no separate pre-login hardware check: it would let anyone exhaust the enclave's resources, and a completed PayPal login is itself the attacker filter. Your browser generates a throwaway encryption key that never leaves this page. Your PayPal identity comes back encrypted to that key — neither the site owner (who holds the PayPal client secret and can issue TLS certificates for this domain) nor the cloud provider (who sees all traffic leaving the machine) can read it. After PayPal verifies you, the enclave mints the hardware proof (an Intel TDX quote) bound to this login and your session, this page audits it, and only a fully green audit decrypts here. This page builds the PayPal link; the enclave never redirects you.

The strongest setup is your own copy: take verify.html from the project's GitHub, save it and open it locally (file://, or use the GitHub Pages copy) — keys are then created only on your machine, anything injected on the enclave's origin only ever sees ciphertext, and this enclave-origin copy refuses key generation by design (Web Auditor Tampering defense).

Flow: click a login button → finish PayPal in the new tab → return here and press “Claim Encrypted Report” below when it appears — the audit runs automatically and a fully green one saves the report to your downloads. If any step fails, nothing is saved, so you are safe to close the tab.

A saved report JSON (💾 offered on the login success page, or the Download button after a passing audit) audits offline in any copy of this auditor, including the GitHub Pages copy or your own saved verify.html. The audit is fail-closed: any red row — including “No valid Silicon Root of Trust” — means the evidence in the report did not verify; a common benign cause is a stale auditor page, so always take the latest verify.html from the project's GitHub. Only trust a report that passes every check.
