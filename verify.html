Hardware-Attested PayPal Login

Prove the machine handling your PayPal login is genuine confidential-computing hardware — then log in.

Before you are sent to PayPal, this page downloads the enclave's live hardware proof (an Intel TDX quote) and audits it here, in your browser. If any check fails, the login does not start. The later steps are optional tools for auditing manually.

Your browser generates a throwaway encryption key that never leaves this page. It is baked into the enclave's hardware quote together with the login challenge, so the proof audited below is proof about this login. Your PayPal identity comes back encrypted to that key — neither the site owner (who holds the PayPal client secret and can issue TLS certificates for this domain) nor the cloud provider (who sees all traffic leaving the machine) can read it. After the hardware audit passes, this page builds the PayPal link; the enclave never redirects you.

Want to inspect the hardware proof before starting a login? Paste the enclave's address (the same page you are on) and run the pre-flight check: it fetches /debug/envelope, audits it in full, and pins the enclave's one-time key. Step 1 then fails if that key changes — so you log into the exact machine you audited.

Fetches /debug/envelope from the enclave, runs the full audit on the live report, and pins its ephemeral key (P_enc). The post-login audit then FAILS if the key changed — you verify the enclave you are about to log in on, not one you met afterwards.

A server owner with a TLS certificate for this domain can inject script into any page it serves — including this one. To remove that trust entirely: save this page from the project's GitHub (verify.html), open the saved file locally (file://), and use the two buttons below in order. Your keys are then created on your machine and the encrypted report is fetched over your own channel — anything injected on the enclave's origin only ever sees ciphertext.

Have a saved report JSON (💾 offered on the login success page, or the Download button that appears after any passing audit)? Upload or paste it below to audit it offline — the saved file works with any copy of the auditor, including the GitHub Pages copy or your own saved verify.html. The optional certificate field additionally binds a saved TLS certificate to the report.

The audit is fail-closed: that alert means the hardware evidence in the report did not verify. The two common benign causes are (1) this auditor page is out of date — always take the latest verify.html from the project's GitHub rather than a cached copy — and (2) the report came from an older enclave build. Only trust a report that passes every check here.
