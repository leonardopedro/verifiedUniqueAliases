Hardware-Attested PayPal Login

Prove the machine handling your PayPal login is genuine confidential-computing hardware — then log in.

There is deliberately no separate pre-login hardware check: it would let anyone exhaust the enclave's resources, and a completed PayPal login is itself the attacker filter. Your browser generates a throwaway encryption key that never leaves this page — automatically, the moment this page opens (the green note below records exactly when). Your PayPal identity comes back encrypted to that key — neither the site owner (who holds the PayPal client secret and can issue TLS certificates for this domain) nor the cloud provider (who sees all traffic leaving the machine) can read it. After PayPal verifies you, the enclave mints the hardware proof (an Intel TDX quote) bound to this login and your session, this page audits it, and only a fully green audit decrypts here. This page builds the PayPal link; the enclave never redirects you. The strongest setup is your own copy: take verify.html from the project's GitHub, save it and open it locally (file://, or use the GitHub Pages copy) — keys are then created only on your machine, anything injected on the enclave's origin only ever sees ciphertext, and this enclave-origin copy refuses key generation by design (Web Auditor Tampering defense).

Flow (two explicit links): your throwaway encryption key is generated AUTOMATICALLY when this page loads — the green note below says exactly when — so there is nothing to click for that. Then pick ONE of the two links: minimal disclosure (“verified status only”) or the full profile. A click prepares the signed login session and that same link turns into “✅ Continue to PayPal →” (opens in a NEW tab); after PayPal returns, the enclave's callback page downloads your still-ENCRYPTED attestation automatically — no landing page. Bring that file back to THIS tab and load it with the “Attestation JSON report” file picker above: this trusted copy decrypts it with the key it generated on load, runs the full hardware audit, and offers the plain JSON for offline auditing. There is deliberately no “claim” button any more — one auto-generated key, two explicit links, one audit. If any step fails, nothing is saved, so you are safe to close the tab.

🔒 Save this enclave's TLS certificate (PEM) — recommended BEFORE logging in

Downloads the exact certificate chain this enclave presented to this browser — the same bytes later recorded inside the report (session_context.tls_certificate_pem). The download connects only to the enclave address below; the PayPal login itself is a separate, direct connection from your browser to PayPal (the enclave never proxies it), so you can save the certificate first and keep your own copy of what you trusted.

⬇️ Download TLS certificate (PEM)
  1. Save enclave-tls-certificate.pem next to your attestation report.
  2. Use it in the audit: load that file with the “Browser TLS certificate (optional)” picker in the “Audit a report you already have” card below — the auditor then cross-checks the chain recorded in the report against this independent copy you fetched yourself.
  3. Inspect it yourself (optional): openssl x509 -in enclave-tls-certificate.pem -noout -subject -issuer -dates, or compare it with a live handshake using openssl s_client -connect enclave-host:443 -showcerts — see the openssl s_client documentation.

Proves — without showing your identity — that this audited quote is bound to a verified PayPal identity, and escrows the plaintext to a recipient key you choose. Everything runs inside this tab (Circom/Groth16 WASM); the identity bytes never leave the page and the proof carries only the hardware-bound hash, the verified bit and ciphertext. The example escrow key below is PUBLIC (testability only — circom.md §7): paste your own BabyJubjub x/y for a real recipient.

Generate the proof below for an authority who must be able to read the identity (police, court, regulator, auditor): paste their BabyJubjub public key here or load it from a file. The key is checked against the curve first, then bound into the proof as a public signal, so the credential proves exactly which key the plaintext was escrowed to and that key cannot be swapped after the fact — the holder opens the credential with scripts/zk-decrypt-escrow.mjs credential.json <private scalar>. Leave both empty to keep the EXAMPLE key (public — zero secrecy). Note: only a BabyJubjub keypair can receive this ciphertext — a PEM/RSA/X.509 key cannot be used by the circuit.
