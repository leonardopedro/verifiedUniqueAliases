# `watchdog/` — self-healing replacement for the TDX confidential VM

Alibaba's console nags: *"We recommend that you create a shutdown script to
save your application data."* The enclave can't take one — it runs its own
PID 1 with no cloud-assistant agent and no shell (AGENTS.md), so nothing
guest-side can run at shutdown. Detection therefore happens **control-plane
side**, in a serverless function that is otherwise idle and costs nothing:

| Leg | What it does | Cadence |
|---|---|---|
| **FC timer** (`poll-5m`) | `DescribeInstances` with our tag; recreate if gone | every 5 min — the guarantee |
| **EventBridge rule** (`pav-prod-watchdog`) | reacts to `ecs:Instance:StateChange`, `ecs:Instance:PreemptibleInstanceInterruption`, `ecs:Instance:SystemFailure.Delete` | seconds — the fast path |

Both legs call the same idempotent `ensure()`:

* **A tagged instance exists → do nothing to it**, whatever its status.
  A deliberately `Stopped` instance is *never* started: that is how the
  operator runs in-place disk rewrites (AGENTS "Instance & Disk Policy").
  Only a **released** instance — gone from the account, e.g. spot eviction —
  is recreated.
* **No tagged instance → `RunInstances` with the captured prod spec**
  (image, `ecs.c9i.large` + `ecs.c9i.xlarge` fallback, TDX
  `SecurityOptions.ConfidentialComputingMode=TDX`, spot `SpotAsPriceGo`,
  vSwitch/SG/zone, 20 GiB `cloud_auto` disk, the enclave's `user_data`, and
  `AllocatePublicIp=false`), tagged `pav-watchdog=prod` so the very next poll
  finds it — then the reserved EIP is bound.
* **The EIP is only bound when the allocation is free.** If it is held by
  another instance the watchdog logs `held-by-other` and walks away — moving
  `101.200.178.251` would silently break ACME for whoever loses it.

Safety properties (each pinned by `test-watchdog.mjs`):

* `ClientToken` is derived from an **hour bucket**, so a burst of retries
  (timer + event + delivery retries) collapses onto one instance, never N.
* Creation retries rotate through the instance-type list (`NoStock` → next
  known-good TDX shape), then **throws**, so the trigger layer retries on its
  own schedule.
* Any HTTP request without the EventBridge delivery token is answered `403`
  *before* a single API call — the endpoint is public.
* Kill switch: `PAV_WATCHDOG_ENABLED=false` (env var beats `config.json`).

## Files

| File | What |
|---|---|
| `handler.js` | FC entry point + `ensure()` (zero dependencies) |
| `rpc.js` | hand-signed Alibaba RPC caller (HMAC-SHA1, same scheme as `/tmp/ecs-call.mjs`) |
| `make-zip.mjs` | builds `dist/pav-watchdog.zip` — the host has no `zip`/`python3`, so DEFLATE + CRC-32 come from `node:zlib` |
| `test-watchdog.mjs` | 13 unit tests against a stubbed RPC layer (`node watchdog/test-watchdog.mjs`) |
| `deploy-watchdog.sh` | full provisioning: tag prod, capture spec + `user_data`, verify the FC role's trust + attach its ECS/VPC policy, function bound to that role, both triggers, EventBridge rule, smoke invoke |
| `dist/` | **gitignored** — holds the enclave `user_data` (real secrets) and the delivery token; regenerated by `deploy` |

## Credentials — function role, no AccessKey

The function runs under the RAM role `FC-ECS-Watchdog-Role` (override with
`PAV_ROLE`). Function Compute assumes it once per invocation and hands the
resulting STS credentials to the handler in `context.credentials`; the handler
signs every ECS/VPC call with them and refuses to run without them. No
AccessKey is created, embedded in the zip, or set as a function env var.

`deploy` keeps the role in the state FC requires:

* **Trust policy** must name the FC service principal `fc.aliyuncs.com`. A role
  trusted only by `agentrun.fc.aliyuncs.com` is a different FC-family service
  and cannot be assumed by Function Compute — `deploy` merges the principal in
  and leaves the existing trust statements untouched.
* **Policy** `pav-watchdog-ecs` (custom) — `ecs:DescribeInstances`,
  `ecs:RunInstances`, `ecs:DescribeImages`, `ecs:DescribeDisks`,
  `ecs:DescribeTags`, `vpc:DescribeEipAddresses`, `vpc:AssociateEipAddress` —
  attached to the role.

Create the role once in the RAM console: Principal type **Cloud Service**,
Principal **Function Compute**, then `deploy` does the rest. The old
`pav-watchdog` RAM user and its access key are unused by this path and can be
deleted (`aliyun ram DeleteAccessKey --UserName pav-watchdog --UserAccessKeyId …`,
then `aliyun ram DeleteUser --UserName pav-watchdog`).

## Operating it

```bash
bash watchdog/deploy-watchdog.sh deploy    # idempotent; re-run any time the spec changes
bash watchdog/deploy-watchdog.sh status    # function + triggers + rule + prod
bash watchdog/deploy-watchdog.sh invoke    # one poll by hand
bash watchdog/deploy-watchdog.sh disable   # kill switch (env var -> false)
bash watchdog/deploy-watchdog.sh enable
bash watchdog/deploy-watchdog.sh selftest          # creates a THROWAWAY instance
bash watchdog/deploy-watchdog.sh selftest-cleanup  # releases it + restores config
```

`selftest` runs the real recreate path against a different tag value
(`pav-watchdog=selftest`, name `paypal-watchdog-selftest`, **no EIP binding**)
so it can never interfere with prod, then prints the new instance for
inspection. Always run `selftest-cleanup` afterwards.

## Known deployment gates (account-level, hit 2026-10-29)

1. **`CreateFunction` → `AccessDenied: Current user is in debt overdue.`**
   Function Compute refuses to provision while the account has an overdue
   balance. Settle the balance in the console, then re-run `deploy`.
2. **EventBridge → `ServiceNotEnable`** — the event bus product is not
   activated for this account. Activate it (console, one click), then re-run
   `deploy`; the rule step is idempotent.

`deploy` treats both as reportable gates rather than crashes: it prints a
`[gate] …` block naming the cause and the console fix, skips only the steps
that depend on the missing piece, and ends with a summary plus a non-zero exit
so an incomplete deployment cannot look successful. With gate 1 open the timer
trigger cannot exist either; with only gate 2 open the 5-minute timer alone
still recovers the box (within 5 minutes instead of seconds).

Everything else in the pipeline is already done and persists across re-runs:
the `pav-watchdog=prod` tag on the enclave, `dist/config.json` (captured spec +
`user_data` + a fresh delivery token) and the verified FC role + policy.

## FC-free alternative: OOS (`oos-watchdog.yaml`, live since 2026-10-30)

`CreateFunction` on this account answers `code: 403, Current user is in debt
overdue` even though there is no overdue invoice, the RAM user holds
`AdministratorAccess`, and other post-paid products provision normally
(a fresh EIP allocates fine). FC has never been activated on the account and
`ros EnableServices '["FC"]'` succeeds without changing anything, so the FC
legs above cannot be deployed until Alibaba clears it.

The watchdog therefore runs on **Operation Orchestration Service** instead:

```bash
bash watchdog/deploy-oos-watchdog.sh deploy          # both templates + start the 5-min chain
bash watchdog/deploy-oos-watchdog.sh schedule on     # restart the chain (cancels, then starts one)
bash watchdog/deploy-oos-watchdog.sh schedule off    # stop the chain
bash watchdog/deploy-oos-watchdog.sh schedule status # live chain + recent ticks
bash watchdog/deploy-oos-watchdog.sh run             # one reconcile now
bash watchdog/deploy-oos-watchdog.sh selftest        # create+delete a THROWAWAY box
bash watchdog/deploy-oos-watchdog.sh status
```

Same contract as `handler.js`: a tagged instance is never touched (a Stopped
box is not started), a released one is recreated with `RunInstances` — TDX,
spot, `cloud_auto` **1 GiB**, no data disk, enclave `user_data` — and the
reserved EIP (`101.200.178.251`, the Cloudflare address) is bound only when the
allocation is `Available`.

Verified live: a selftest execution produced a real TDX box with
`cloud_auto 1GiB system` and left the reserved EIP alone; a prod-tagged run
returned `{"instanceId":"i-2zed3wq8aubeph9na28i","eipStatus":"InUse"}` without
creating anything.

Three constraints found the hard way, all encoded in the files:

* **Auto Scaling cannot do this.** `ALIYUN::ESS::ScalingConfiguration` has no
  `SecurityOptions` (no TDX) and floors the system disk at 20 GiB; ECS
  documents that confidential-computing instances can only be created through
  `RunInstances`, which is what OOS drives.
* **The enclave config must not be an OOS parameter.** `ListExecutions` echoes
  execution parameters in cleartext (one bring-up run leaked the config and
  the record had to be deleted), a secret parameter value is capped at 4096
  chars while the config is ~5.8 KB base64, and `{{ oos-secret:name }}` is
  rejected in task parameters. `deploy-oos-watchdog.sh` therefore injects it
  at deploy time from the gitignored `dist/config.json`; the repo copy keeps a
  `__USERDATA_B64__` placeholder.
* **OOS state configurations refuse user templates** here
  (`EntityNotExists.Template` for a template `ListTemplates` reports as `v5` —
  tried by name, by template id, by ARN-like name, with `TemplateVersion` and
  with `ResourceGroupId`), so OOS's own scheduler cannot drive this template.

### The cadence: a self-rearming heartbeat (`oos-heartbeat.yaml`)

Cost: **OOS itself is free** ("您可以免费使用OOS，但需要为您创建的执行内所涉及的云资源进行付费"),
so a 1-minute cadence costs nothing but execution records — 1,440 heartbeats/day,
each one `DescribeInstances` + `DescribeEipAddresses`. Default is `PT1M`
(`PAV_OOS_INTERVAL=PT5M` to widen it). Note the spot notice is 5 minutes, so
the extra frequency mostly shortens the blind window for non-spot losses
(owner release, system failure).

Every native scheduler is closed on this account, each verified live on
2026-10-30:

| Candidate | Result |
|---|---|
| OOS state configuration (`CreateStateConfiguration`) | `EntityNotExists.Template` for any user template; plus `ScheduleType: cron` → *"Cron schedule type is not supported right now."* and `rate` documents a **30-minute minimum** |
| EventBridge rule → OOS | EventBridge has no OOS target type (FC, MNS, RocketMQ, RabbitMQ, Kafka, SLS, RDS, HTTP(S), API destination, FnF, SAE, K8s, DingTalk, SMS, mail, DataHub, EventBridge — but not OOS) |
| CloudFlow / FnF schedule | `AccessDenied: FnF service is not enabled for current user` |
| Function Compute timer | still `code: 403, Current user is in debt overdue` |
| Auto Scaling scheduled task | cannot produce TDX at 1 GiB (see above) |

What does work is OOS calling OOS: `ACS::ExecuteAPI` with `Service: OOS` runs
normally, so `pav-watchdog-hb` is a **chain of exactly one successor per tick**:
`sleep {{ interval }}` (PT1M) → `rearm` (start one successor) → `reconcile`
(start `pav-watchdog`, which is idempotent and never touches an existing tagged
box).

**Ordering is the whole design.** Reconnecting `rearm` before the sleep makes
every execution spawn a successor the instant it starts, and each of those does
the same: observed live, 4 running heartbeats at 6 minutes climbing to 100
executions and 98 waiting. `rearm` must come *after* the wait, and before the
reconcile so a failing reconcile cannot break the chain.

Verified live: one chain → 1-2 executions in steady state (one reconciling, one
sleeping), a PT1M tick landing inside 60 s, and the full recreate path proven by
actually releasing prod (see below).

#### Proven end to end (2026-10-30, real release)

Prod `i-2zed3wq8aubeph9na28i` was force-deleted at 10:36Z. The chain rebuilt it as
`i-2zef7xhigzn70d6zwimj` — same image `m-2ze2z92s2ewrax782f2i`, `ecs.c9i.large`,
same zone/vSwitch/SG, `cloud_auto` **1 GiB** disk, `user_data` sha256 identical to
`dist/config.json`, and the reserved EIP bound. Two defects surfaced and are fixed:

* **`InternetMaxBandwidthOut: 5` made the rebuild unbindable.** An auto-assigned
  `natpublicip` blocks EIP association (`EIP_CAN_NOT_ASSOCIATE_WITH_PUBLIC_IP`,
  "instance already bind natpublicip, cannot bind eip"). The template now uses
  `InternetMaxBandwidthOut: 0` + `AllocatePublicIp: false`, so the reserved EIP is
  the only public path — which is also what the Cloudflare DNS-01 token pin
  requires.
* **`ListTemplates` matches on a name prefix**, so `template_exists pav-watchdog`
  also listed `pav-watchdog-hb`, and `deploy` tried to re-create an existing
  template and failed. It now matches the exact name across the whole list.

#### Spot-interruption capture (EventBridge → SLS, live 2026-10-30)

OOS cannot consume the notice, so the notice is captured instead:

| Piece | Value |
|---|---|
| Rule | `pav-spot-interruption` on bus `default` (cn-beijing), `ENABLE` |
| Pattern | `{"source":[{"prefix":"acs.ecs"}],"type":[{"prefix":"ecs:Instance:PreemptibleInstanceInterruption"}]}` |
| Sink | SLS project `pav-events`, logstore `spot-notices`, TTL 30 days |
| Role | `pav-eventbridge-sls` — trusts `eventbridge.aliyuncs.com`, has `AliyunLogFullAccess` |

Two traps found while building it:

* **The pattern syntax is the old one.** `TestEventPattern` returns `false` for the
  newer `{"source":{"stringEqual":[...]}}` form this CLI's `CreateRule` help
  advertises, and `true` for the prefix-list form — so use the prefix form or the
  rule silently matches nothing.
* **The delivery path still ends at SLS, not OOS.** EventBridge has no OOS target,
  so the notice is recorded but cannot yet trigger a rebuild; the 1-minute poll
  stays the primary detector and SLS is the forensics trail (30 days).

`ecs:Instance:RebalanceRecommendation` (the earlier "you may be reclaimed"
warning) is a one-line addition to the pattern if you want that captured too.

Known weakness: if the `rearm` task itself fails (OOS API outage) the chain dies
silently. `schedule status` prints the live chain, so a dark tip is visible there
and in the account's execution history. The structural fix is event-driven: ECS
delivers a preemptible-instance **interruption notice ~5 minutes before a spot
reclaim** (a CloudMonitor/EventBridge event — `ecs:Instance:PreemptibleInstanceInterruption`),
and the enclave could in principle act on it, but that requires giving the
enclave `ecs:RunInstances` rights (a real expansion of its authority, beyond the
PayPal secrets and DNS-01 token it already holds), so it stays credential-free
and the control plane polls instead.
