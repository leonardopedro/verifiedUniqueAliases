RSA ZK Escrow Credential

Prove — without revealing your identity — that you hold an RSA key (PGP/GPG or S/MIME, the kind used on encrypted whistleblower & police mail), bound to a statement, with the plaintext escrowed to a recipient key you choose.

🛡 What this does. It produces one JSON credential containing: (a) a zero-knowledge proof of possession of the RSA private key — a Guillou–Quisquater-style Fiat–Shamir proof (SHA-256 challenge, no trusted setup, no circuit, no ceremony); nobody can forge it without the private key, and it reveals nothing about the key beyond its public part; (b) your identity payload encrypted to the recipient's key — as a JSON envelope (RSA-OAEP + AES-256-GCM), a real OpenPGP message the police can open with gpg --decrypt, or a real S/MIME CMS blob for openssl cms -decrypt — plus its SHA-256 hash in the clear, so anyone can see which identity is committed while only the recipient can read it.

(c) optionally, the payload is the enclave-SIGNED PayPal identity from a green verify.html audit (attested mode): the escrow then holds “valid verified PayPal data about some user” that only the recipient can read — while you learn nothing, the public challenge pins report_sha256 + the signed user hash, so anyone holding the report can tie the ciphertext to that hardware quote. Everything — parsing, proving, encrypting, verifying — happens in this tab. No network requests are made at all (this file loads no scripts, fonts or artifacts; disconnect and it still works).

⚖ What it does NOT prove. With no circuit there is no in-proof binding between the ciphertext and the hash: the proof binds you to this ciphertext+hash pair, and the recipient completes the binding after decrypting (SHA-256 of the plaintext must equal identity_hash — the verifier below checks this when you supply the recipient key). Statement fields (nonce, domain) are covered by the challenge, so they cannot be swapped after the fact.
⚠ Threat-model honesty. A secret key typed or pasted into any web page is only as safe as the machine rendering it: a compromised browser, OS or extension can read it. For real whistleblower use: Tails/Tor Browser on a clean machine, and prefer keys with no passphrase exported only for this session — on a trusted machine run gpg --pinentry-mode loopback --passphrase '' --export-secret-keys --armor NAME to get an unencrypted block, prove, then delete it. Passphrase-protected secret keys are refused by design (we will not handle your passphrase). The public side needs no precautions: any reader can verify a credential.

Paste any of: an OpenPGP PUBLIC/SECRET KEY block (GPG), an X.509 CERTIFICATE (S/MIME), a RSA/PRIVATE KEY PEM, or raw n=… / e=… lines. To prove, the private part is required (PGP secret key, PKCS#1/PKCS#8 PEM). Detection is automatic.
